# AETHERIS v0.3.0 发布说明

发布日期：2026-08-19

AETHERIS v0.3.0 将阅片、报告、检查申请和机构管理串成了一套完整的医学影像工作流。本版本同时强化了 GPU 阅片能力、服务端权限边界、审计留痕和双平台桌面分发。

> AETHERIS 目前仍是研究与工程项目，未经临床验证，不应用于诊断或直接临床决策。

## 重点更新

### 1. 独立患者检查队列

- 登录后默认进入全屏患者检查队列，一行对应一次检查。
- 支持服务端分页、排序，以及来源医院、报告状态、模态、部位和日期组合筛选。
- 双击检查进入阅片；阅片窗口保留“检查 → 序列”患者上下文树。
- 管理员和技师可以从检查行进入 DICOM 标签编辑。
- 已入库检查会显示申请单和报告状态，不再依赖客户端本地导入入库。

### 2. GPU 阅片与跨序列协同

- GPU Oblique MPR 支持任意角度斜切、可旋转十字线和三平面正交联动。
- 基于 `ImageOrientationPatient`、`ImagePositionPatient`、`PixelSpacing` 的患者物理空间重建，支持各向异性体素和真实物理测量。
- 支持跨序列滚动/窗宽窗位同步与定位线。
- 支持最多 3×3 多序列分屏，每个窗格拥有独立渲染与交互状态。
- 体渲染提供窗宽窗位、旋转、平移和缩放鼠标手势。

### 3. 独立报告工作台

- 报告在独立窗口中完成，阅片 Viewer 保持专注于图像显示和操作。
- 报告按检查管理，一次检查对应一份诊断报告。
- 结构化模板覆盖所见、印象、建议和阳性标记。
- 支持保存草稿、提交审核、审核签发、签发后修订和不可变版本快照。
- 报告工作台展示患者/机构信息、关联申请单临床指征和完整审核时间线。

### 4. 机构级报告审核闭环

- 管理员可以在“管理控制台 → 机构设置”开关报告审核闭环，设置即时生效并持久化。
- 开启后，医生只能保存草稿或提交审核，不能绕过审核直接签发。
- 审核人需要 `review_report` 权限，且不能审核自己的报告。
- 审核人可以直接签发，或修正报告后签发；修正行为保留作者署名、审核人标记和 `reviewer_modified` 审计事件。
- 关闭审核闭环时保留草稿直签流程，适用于单医生或演示环境。

### 5. 检查申请单

- 支持先创建申请单、后上传影像，再由技师手动匹配检查。
- 支持直接从患者检查列表为已入库检查开具申请单，患者快照和 Study 由服务端读取。
- 申请单包含患者、模态、部位、申请类型和临床指征，状态按“待执行 → 已执行 → 已完成”流转。
- 报告签发或审核完成后，关联申请单自动标记为已完成。

### 6. 管理控制台与工作量

- 账号管理支持创建账号、首次登录强制改密、停用/启用和会话吊销。
- 用户在登录页提交“用户名 + 新密码”的重置申请；密码仅保存 Argon2id 哈希，管理员只能批准或驳回，不能看到新密码。
- 管理员可以授予或撤销报告审核权限。
- 工作量报表按用户和日期范围统计报告状态、签发版本、完成审核、审核修正和申请单数量。
- 设备注册、来源归属、用户授权、密码重置和机构设置均由服务端进行角色与机构边界校验。

### 7. DICOM 与工程改进

- DIMSE 协商清单增加 RLE Lossless（`1.2.840.10008.1.2.5`）。
- 队列、报告、申请单和管理接口均执行机构隔离与服务端权限校验。
- 密码重置、报告审核、申请单绑定和机构设置变更均保留审计记录。
- Windows 安装器版本和 artifact 名称统一从 `tauri.conf.json` 的 `0.3.0` 读取。
- macOS 内置服务启动日志不再输出明文随机密码。

## 从 v0.2.0 升级

1. 停止正在运行的 AETHERIS 服务。
2. 备份 PostgreSQL 数据库和 DICOM 存储目录。
3. 安装 v0.3.0 并启动服务。
4. `pacsd` 启动时会执行内嵌的 SQLx 数据库迁移；迁移包含报告审核、机构审计、搜索索引、密码重置审批和申请单表。
5. 管理员登录后检查账号权限、设备归属和“机构设置 → 报告审核闭环”状态，再进行临床工作流冒烟。

不要在没有数据库与影像存储备份的情况下覆盖生产环境。

## 已知限制

- macOS 安装包仅支持 Apple Silicon；当前使用 ad-hoc 签名，未进行 Apple Developer ID 签名或 notarization。
- Windows 安装包面向 Windows 10/11 x64，安装需要管理员权限；当前未配置商业代码签名。
- macOS 原生 GUI 完整工作流仍需在可保持桌面会话的环境人工冒烟。
- Windows 安装、启动、登录和临床工作流仍需在 Windows 10/11 x64 实机人工冒烟。
- C-MOVE/C-GET SCP 尚未实现；影像取回使用 WADO-RS 或 C-STORE。
- STOW-RS 当前支持 Part 10 multipart，DICOM JSON/bulk-data 变体仍在路线图中。
