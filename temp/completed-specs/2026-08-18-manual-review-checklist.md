## 场景 A：报告审核闭环（review_required = true）

### A1 作者送审
- [ ] A1.1 用 **医生A** 登录，从队列页双击进入该检查，打开报告工作台，起草报告（所见/印象/建议）
- [ ] A1.2 点击「**提交送审**」（rw-submit 按钮，仅作者且草稿态可见）
- [ ] 预期：报告状态变为「**待审核**」；送审后内容对作者变为只读

### A2 队列页状态
- [ ] A2.1 返回队列页（或刷新）
- [ ] 预期：该检查行的报告状态徽标显示「**待审核**」（submitted，区别于旧的待书写/书写中）

### A3 审核人开始审核
- [ ] A3.1 用 **医生B** 登录，打开该检查报告
- [ ] A3.2 点击「**开始审核**」（rw-review-start）
- [ ] 预期：报告状态变为「**审核中**」，界面显示审核人姓名；作者侧该报告只读

### A4 直接签发（不需要修改）
- [ ] A4.1 审核人选择「**无需修改，直接签发**」（或"修改后签发"按钮在不进入编辑时直接确认签发——以界面实际按钮为准）
- [ ] 预期：报告状态变为「**已签发**」，队列页徽标同步；作者可看到审核时间线（提交→开始审核→签发）

### A5 修改后签发 + 作者错误计数
- [ ] A5.1 用 **医生A** 再起草一份报告并提交送审（或复用同一检查走 amend）
- [ ] A5.2 用 **医生B** 开始审核 → 点「**修改后签发**」→ 修改报告内容（所见/印象/建议任一处）→ 确认签发（按钮变为「确认修改并签发」）
- [ ] 预期：签发成功；报告内容为**修改后**版本
- [ ] A5.3 验证错误计数（当前无工作量报表，走库）：
      `SELECT COUNT(*) FROM report_review_events WHERE action='reviewer_modified';` 应 ≥1
      （可按报告归属聚合到医生A）
- [ ] A5.4 版本留痕：报告版本列表里修改版本的存在（若界面有版本查看入口），署名/修改人留痕符合「方案A：作者署名保留 + 审核人已修改标记」

### A6 负向用例：权限与同作者
- [ ] A6.1 用 **医生A**（作者）在「待审核」状态尝试开始审核
- [ ] 预期：被拒绝（「作者不能审核自己的报告」提示）
- [ ] A6.2 用 **技师T**（未授予 review_report）打开待审核报告
- [ ] 预期：审核按钮**置灰**，提示「请管理员在账号管理中授予"可审核报告"权限」；直接调 API 也应被后端拒绝（权限校验在后端）

### A7 时间线 / 审计
- [ ] A7.1 作者或审核人打开已签发报告，查看审核时间线
- [ ] 预期：显示提交（谁/何时）、开始审核（谁/何时）、签发（谁/何时）事件；审核人修改过的报告有「审核人已修改」痕迹；审核意见可见

## 场景 C：账号管理（管理控制台 → 账号管理 tab）

- [ ] C1 admin 进入「管理控制台 → **账号管理**」：应有账号列表（角色/状态/权限列）
- [ ] C2 创建账号：用户名 + 临时密码（≥12 位、不含用户名）
- [ ] 预期：创建成功提示「首次登录必须修改密码」；新账号首次登录被要求改密
- [ ] C3 给医生B 勾选/取消「可审核报告」权限，保存后立即生效（回场景 A6.2 复查可反证）
- [ ] C4 停用账号：确认框提示「会话将被吊销」→ 停用后该账号登录被拒
- [ ] C5 启用账号：恢复后可正常登录
- [ ] C6 权限隔离：用**医生A**（非 admin）尝试打开管理控制台
- [ ] 预期：无入口或被拒；radiologist/technician 不可管理账号

## 场景 D：密码重置审批流程

- [ ] D1 用 **医生B** 在登录页点「**忘记密码？**」→ 申请对话框输入用户名 + 新密码（≥12 位）+ 确认
- [ ] 预期：提交成功提示「等待管理员审批」（不直接改密）
- [ ] D2 用 **admin** 进「管理控制台 → **密码重置**」tab
- [ ] 预期：看到该申请，**界面不显示新密码内容**（仅哈希存储，管理员不可见）
- [ ] D3 批准该申请
- [ ] 预期：医生B 用新密码登录成功；旧密码失效
- [ ] D4 再次申请一个，admin **驳回**
- [ ] 预期：医生B 用新密码登录失败（或收到驳回提示，视实现），旧密码仍有效
- [ ] D5 审计：密码重置申请/批准/驳回事件留痕（audit 表可查）
