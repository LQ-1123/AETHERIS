## 场景 A：申请单创建与列表（技师端）

- [ ] A1 **入口**：用技师T 登录 → 界面可见「申请单」入口（独立页或队列页 tab，按实施为准）
- [ ] A2 **新建**：填写患者信息（患者ID/姓名）+ 检查请求（模态 CT、部位 CHEST、申请类型 平扫）+ 临床指征（如「咳嗽两周，CT 排除肺炎」）→ 保存
- [ ] 预期：创建成功，列表出现该申请单，状态「**待执行**」，创建人=技师T，时间正确
- [ ] A3 **必填校验**：留空患者ID 或 部位/模态 → 保存被拒，提示缺失项
- [ ] A4 **列表筛选**：按状态（待执行/已执行/已完成）筛选 → 结果正确
- [ ] A5 **编辑**：待执行态可修改（如改临床指征）→ 保存生效；已执行/已完成态编辑被拒（或只读）
- [ ] A6 **负向**：申请单内容含超长文本/非法字符 → 后端拒绝（400），不静默截断

## 场景 B：绑定检查（申请单 ↔ study）

- [ ] B1 **绑定**：技师T 在「待执行」申请单上选择「绑定检查」→ 从检查列表选一个已入库检查 → 绑定
- [ ] 预期：申请单状态变「**已执行**」，记录关联的检查（study）
- [ ] B2 **重复绑定**：把同一检查绑定到**第二个**申请单
- [ ] 预期：被拒绝并提示（一个检查只对应一份申请，实施时应有此约束）；若实施允许则记录实际行为
- [ ] B3 **绑定不存在的检查**：直接传无效 study_uid
- [ ] 预期：后端拒绝（404/400），不产生脏数据
- [ ] B4 **取消/解绑**（若实施支持）：解绑后回到待执行态
- [ ] 预期：解绑后状态与数据一致

## 场景 C：医生端展示（申请信息辅助写报告）

- [ ] C1 用医生A 打开**已绑定检查**的报告工作台
- [ ] 预期：工作台可见该检查的申请信息（临床指征/申请技师/申请时间）
- [ ] C2 队列页该检查行有「**有申请单**」标记（若实施）
- [ ] C3 打开**未绑定申请单**的检查 → 无申请信息展示，不报错

## 场景 D：状态联动（报告闭环 → 申请单完成）

- [ ] D1 对已绑定申请单的检查：医生A 写报告 → 送审 → 医生B 审核签发
- [ ] 预期：签发/审核完成后，该申请单状态自动变「**已完成**」
- [ ] D2 已完成申请单：不可再编辑/绑定；列表筛选「已完成」可见
- [ ] D3 未走签发（仅草稿）的检查 → 申请单保持「已执行」，不提前完成

## 场景 E：工作量报表（admin 端）

- [ ] E1 **入口**：admin 登录 → 管理控制台 → 新增「工作量」tab
- [ ] E2 **时间范围**：切换 日/周/月/自定义起止 → 数据随范围变化正确
- [ ] E3 **医生指标抽样核对**：取一名医生，核对其 报告数（按状态：草稿/送审/审核中/已签发）、被审核修改次数（错误数）、签发数 —— 与报告列表/审核事件实际一致
- [ ] E4 **技师指标**：技师申请单创建数与实际一致
- [ ] E5 **空数据**：无数据的时间范围显示空态，不报错
- [ ] E6 **导出**（若实施 CSV）：导出内容与表格一致，编码正常（中文不乱码）
